# Summonr API (locked)

Status: locked

Every job this harness performs is a row on this page. A job not on this page
is not a job; a second name for a row is a defect.

Two piles, and both get said out loud:

| Pile | What | Home |
| --- | --- | --- |
| **Menu** | jobs the model, the CLI, or a config file may call | this page |
| **Kitchen** | everything rustc still lets you call | a local census, generated by `scripts/api-census.py` (see below) |

Never answer "that's all the API" from this page alone. Nine menu jobs sit on
999 functions; the other 990 are plumbing, and the census says which is which.

## The rule

1. A new shared helper is a row on this page in the same change, or it stays
   private.
2. One job, one name. A synonym is not a job.
3. Names come from source. Do not mint one for a surface that has no identifier.
4. A public item that is not a row here is a candidate for `pub(crate)`.
5. `src/tui` has its own page, [`tui.md`](tui.md), under the same four rules.

Compiled modules are the built-in modules: keep the binary small. Skills, MCP, hooks,
and `run_command` CLIs are user extras outside the process. Do not add a
plugin host or a second name for `skill`, `mcp`, or `run_command`.

## Model-facing jobs

The tool schemas. Six core, seven behind a module, a workspace file, or a person at the session.

| Job | Where | Gating |
| --- | --- | --- |
| `read` | `tools/catalog.rs::read` | always |
| `search` | `tools/catalog/search.rs::search` | always; `workspace/search.rs` builds the query, `search/walk.rs::run` walks under `search_secs`, `search/filter.rs` owns `name`, `newer`, and `group`, `search/render.rs` owns the result text |
| `edit` | `tools/catalog.rs::edit` | always |
| `write` | `tools/catalog.rs::write` | always |
| `run_command` | `tools/catalog.rs::run_command` | always outside a read-only research child; there only with a sandbox; the schema is frozen per session |
| `todo` | `tools/catalog.rs::todo` | steps and goal runs only; owns the itemized Work step list |
| `skill` | `tools/catalog.rs::skill` | `.summonr/skills` present |
| `lsp` | `tools/catalog.rs::lsp` | `lsp` module on |
| `web` | `tools/catalog.rs::web` | `search` module on (off by default) |
| `browser` | `tools/catalog/browser.rs::browser` | `browser` module on (off by default); `browser.rs` holds one Charm `Session` per summonr session, started on first use, in its own profile under `~/.summonr/browser/profiles`, and saves its cookies after every call; every URL passes `web::allowed_url`, uploads pass the registry read policy (`ToolRegistry::resolve_read`), and opening arms Chrome's blocked-URL list with `web::PRIVATE_URL_PATTERNS` so redirects cannot contact private hosts; a read-only registry never advertises or dispatches it; `web` with `url` renders through it when `browser/wall.rs` sees a page that needs JavaScript |
| `task` | `runtime/child.rs::definition` | interactive sessions (TUI, ACP) at depth 0 with the `task` module on; the Modules rows in `/settings` or `task = false` under `[modules]` turn it off; an optional `agent` names a plugin agent from `<agents>`, whose instructions open the child's first message and whose `tools` deny other tools at call time (`ToolRegistry::restrict_to`, names through `hooks::builtin`) |
| `ask` | `runtime/turn/ask.rs::definition`, `Loop::ask` | TUI sessions at depth 0, the only ones with a steering channel; one to four questions, each a field of an `mcp::Form` with no `server`: options become `Choice` or `Choices` with `custom` set, no options a text field; the call runs through `Loop::elicit`, so MCP servers and the model share one dialog, one `grant_wait_secs` wait, and one dismissal; the dialog picks with `↑`/`↓`, toggles with `space`, and Enter takes the highlighted single choice, while Enter on a multi-choice with nothing toggled gives no answer; text typed while the dialog is open answers the current question, and a steer sent earlier never answers it |
| `<server>__<tool>`, `mcp` | `mcp/defer.rs` `Hub::definitions` | `mcp` module on; project servers need approval; a read-only research child does not treat `readOnlyHint` as read-only; a server over `MCP_DEFER_BYTES` of schemas is listed under `mcp` |
| `agents`, `send`, `inbox`, `board` | `mail/tools.rs::definitions` | `mail` module on, or `SUMMONR_MAIL` set to anything but `off`; the session must be on the roster; `board` set and `send` are off in a read-only research child |

A read-only research child is offered `read`, `search`, `run_command`, `skill`, and `web` when `search` is on, plus the
mail tools when mail is on; `send` and `board` set refuse there.

Peer mail has no server. Other agent CLIs reach the same files through
`summonr mail` (`mail/cli.rs::run`).

### Checked and kept

These look like duplicates by name. They are not. The difference is payload or
layer, and each one was read before it was written down here:

- `Policy {Single, Steps, Goal}` is not `WorkKind {Single, Steps,
  Goal}`. `Policy` is the configured budget, `WorkKind` is the reported kind,
  and `durable/work.rs::Work::progress` converts one to the other on purpose.
- `work::Observation {File, Stdout}` is not `steps::Item {File, Stdout {command,
  expected}}`. The plan contract names the command and the expectation; the
  recorded observation does not.
- `web::Backend` (search provider), `secret::Backend` (key store), and
  `tools::sandbox::Backend` (platform) are three domains that share a word.
- `Role` is a message role in `provider.rs` and a workflow seat in
  `workflow.rs`. `Source` is span provenance in `chat.rs` and credential origin
  in `secret.rs`.
- `Frame` is JSON-RPC framing and the Anthropic `Event` is a wire event.
  Neither belongs to the session family.
- The progress types describe different lifecycles: a step can be `Blocked`, a
turn cannot. `diag` is about rendering progress once, not about one enum for
  every object.

Full evidence and line numbers: the local audit, systems S1, S2, and S7.

## Unify order

Ranked from the census, by job.

1. One session event. Four types describe the same facts today, so this needs
   a design pass before code moves: the on-disk log has to stay readable.
   Proof is replay: a captured `session.jsonl` re-reads to an identical
   transcript through the shipped `session::Replay`.
2. The three god objects: `App` 125 functions in one file, `Loop` 84 in
   `runtime/configure.rs` (74 `pub`), `SessionDriver` 65.
3. Ten grid builders onto one row painter. `settings.rs` is 915 of 1,029 lines.
4. One atomic writer. Landed at `durable/store.rs::write`; each remaining
   direct write is a different job, such as a job log opened as stdio.
5. `pub` that is not reachable: 203 `pub` functions, many inside private
   modules.
