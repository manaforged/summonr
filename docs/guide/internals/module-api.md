# Summonr API (locked)

Status: locked

Every job this harness performs is a row on this page. A job not on this page
is not a job; a second name for a row is a defect.

Two piles, and both get said out loud:

| Pile | What | Home |
| --- | --- | --- |
| **Menu** | jobs the model, the CLI, or a config file may call | this page |
| **Kitchen** | everything rustc still lets you call | a local census, generated by `scripts/api-census.py` (see below) |

Never answer "that's all the API" from this page alone. The census counts
every function, and `scripts/api-function-map.py` files each one under a menu
job or named plumbing.

## The rule

1. A new shared helper is a row on this page in the same change, or it stays
   private.
2. One job, one name. A synonym is not a job.
3. Names come from source. Do not mint one for a surface that has no identifier.
4. A public item that is not a row here is a candidate for `pub(crate)`.
5. `src/tui` has its own page, [`tui.md`](tui.md), under the same four rules.

Compiled modules are the built-in modules: keep the binary small. Skills, MCP, hooks,
and `run_command` CLIs are user extras outside the process. Do not add a
plugin host or a second name for `skill`, `mcp`, or `run_command`.

## Model-facing jobs

The tool schemas. Six core, seven behind a module, a workspace file, or a person at the session. Every schema, MCP ones included, passes `tools::args::tool`, which folds a root `anyOf`, `oneOf`, or `allOf` into one `type: object` root (the branches' properties merge, fields every `anyOf`/`oneOf` branch requires stay required, and `allOf` requirements add up), because xAI and other providers reject a union root.

| --- | --- | --- |

| `search` | `tools/catalog/search.rs::search` | always; `workspace/search.rs` builds the query, `search/walk.rs::run` walks under `search_secs`, `search/filter.rs` owns `name`, `newer`, and `group`, `search/render.rs` owns the result text |

| `run_command` | `tools/catalog.rs::run_command` | always outside a read-only research child; the schema is frozen per session |

| `agents`, `send`, `inbox`, `board` | `mail/tools.rs::definitions` | `mail` module on, or `SUMMONR_MAIL` set to anything but `off`; the session must be on the roster; `board` set and `send` are off in a read-only research child |

A read-only research child keeps the parent's tool list and can call `read`, `search`, `skill`, and `web` when `search` is on, plus the
mail tools when mail is on; `send` and `board` set refuse there.

Peer mail has no server. Other agent CLIs reach the same files through
`summonr mail` (`mail/cli.rs::run`).

### Checked and kept

These look like duplicates by name. They are not. The difference is payload or
layer, and each one was read before it was written down here:

- `Policy {Single, Steps, Goal}` is not `WorkKind {Single, Steps,
  Goal}`. `Policy` is the configured budget, `WorkKind` is the reported kind,
  and `durable/work.rs::Work::progress` converts one to the other on purpose.
- `work::Observation {File, Stdout}` is not `steps::Item {File, Stdout {command,
  expected}}`. The plan contract names the command and the expectation; the
  recorded observation does not.
- `web::Backend` (search provider) and `secret::Backend` (key store) are two
  domains that share a word.
- `Role` is a message role in `provider.rs` and a workflow seat in
  `workflow.rs`. `Source` is span provenance in `chat.rs` and credential origin
  in `secret.rs`.
- `Frame` is JSON-RPC framing and the Anthropic `Event` is a wire event.
  Neither belongs to the session family.
- The progress types describe different lifecycles: a step can be `Blocked`, a
turn cannot. `diag` is about rendering progress once, not about one enum for
  every object.

Full evidence and line numbers: the local audit, systems S1, S2, and S7.

## Unify order

Ranked from the census, by job. Current counts come from
`python3 scripts/api-census.py` and `scripts/api-function-map.py`, not
from this page.

1. One session event. Four types describe the same facts today, so this needs
   a design pass before code moves: the on-disk log has to stay readable.
   Proof is replay: a captured `session.jsonl` re-reads to an identical
   transcript through the shipped `session::Replay`.
2. The three god objects: `App`, `Loop`, and `SessionDriver`.
3. Grid builders onto one row painter.
4. One atomic writer. Landed at `durable/store.rs::write`; each remaining
   direct write is a different job, such as a job log opened as stdio.
5. `pub` that is not reachable, much of it inside private modules.
